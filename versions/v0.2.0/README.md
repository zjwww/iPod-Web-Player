# iPod Web Player

[简体中文](README.zh-CN.md) · [Open the player](https://zjwww.github.io/iPod-Web-Player/)

An independent educational click-wheel music player. **Not affiliated with, sponsored by, or endorsed by Apple.** Current release: **0.2.0 — 2026-10-26**.

## Play in your browser

Open **https://zjwww.github.io/iPod-Web-Player/** and choose **Play test music**, or select a song from the device's Songs menu. Hosted playback needs no Node.js, PowerShell, account, or installation. Playback starts after a user action.

An original 24-second composition, **First Spin**, is included at `versions/v0.2.0/dist/audio/first-spin.wav`: 22,050 Hz, mono, 16-bit PCM WAV, MIT licensed. It is reproducibly generated by `tools/prepare-pages.cjs` from `dist/library.js:createDemo`; `audio-provenance.json` records its SHA-256. No commercial song or Apple Music preview is included.

Use Add music, Choose folder where supported, or drag-and-drop to import your music. Imports are copied into the current browser's IndexedDB and are never uploaded. **Clear imported music** removes those copies, retaining the included track and original files.

## Controls

- Drag around the wheel, trace it with your finger, use a mouse wheel, or press ↑/↓ to browse. Center/Enter selects; MENU/Escape returns.
- While playing, Center switches between seeking and volume. Bottom plays/pauses; sides skip tracks; hold sides to seek. Hold MENU to toggle backlight.
- Playlists and Artists group songs using available metadata. MP3 ID3 tags are read; other files use filename/folder fallbacks.
- Readable bilingual menus, system light/dark colors, and responsive immersive view are included. The battery icon is decorative.

## iOS Safari and PWA

Open the **HTTPS Pages URL in Safari**, then tap Play test music once. AudioContext resume and native audio playback are called synchronously inside user interaction, without first awaiting a download. The test track uses standard PCM WAV. The offline service worker and optional Node server support single byte ranges for seeking.

Use **Share → Add to Home Screen** (enable Open as Web App when offered). Native fullscreen is detected, with immersive layout as fallback. Installation does not guarantee fullscreen, unlimited background/lock-screen playback, or permanent storage; these remain controlled by the OS/browser.

The worker saves the shell, catalog and included music under the deployment path; cache names and manifest identity are scoped to that path. Imported music is separate in IndexedDB. Clearing website data can remove music and offline resources; the in-app clear button removes only imports. Ordinary HTTP LAN access can play audio but normally cannot enable service-worker caching.

**Verification scope:** Windows Chrome and Edge playback are checked separately. Mobile portrait/landscape layout and Safari-specific paths have desktop/static checks. Physical iPhone/iPad Safari, Home Screen installation, touch and lock-screen audio still need real-device verification. Viewport simulation is not Safari testing. See versioned `VERIFICATION.md`.

## Add hosted music

Place redistributable files in `versions/v0.2.0/dist/audio/` and add records to `dist/tracks.json` while preserving `version: 1`:

```json
{"id":"my-track","name":"My Track","artist":"Artist","album":"Test Album","url":"./audio/my-track.mp3","type":"audio/mpeg"}
```

IDs must be unique; use relative same-site URLs. External URLs and paths outside the player directory are rejected. Titles are rendered as text. Repository music is public; browser imports stay private. Make a new `versions/vX.Y.Z/` for later releases and update the workflow/cache version rather than overwriting a delivered release. Offline installation downloads included catalog music, so consider total size before adding a large library.

MP3 is the first choice for broad compatibility. PCM WAV/FLAC are useful lossless choices. AAC/M4A, Ogg/Opus, WebM and AIFF depend on codec/browser/OS support. Picker acceptance is not a playback guarantee. DRM-protected files are unsupported.

## Optional local Windows launchers

`versions/v0.2.0/Start-Player.cmd` uses existing Windows PowerShell 5.1 + .NET HttpListener at `http://localhost:8765/v0.2.0/`. It installs nothing and starts an ordinary hidden process, not a Windows system service. Stop/check with Stop-Player.cmd / Status-Player.cmd; closing the launcher does not stop it.

Start-LAN.cmd uses an **already installed Node.js on PATH**, port 8766, with matching Stop-LAN.cmd / Status-LAN.cmd. Node is optional for development and never needed by Pages visitors. Scripts do not modify the firewall.

## Development and deployment

No npm packages or build-time downloads are required. With Node available:

```sh
node --test versions/v0.2.0/tests/*.test.cjs
node versions/v0.2.0/tools/audit-release.cjs --tracked
node versions/v0.2.0/tools/build-pages.cjs
node versions/v0.2.0/server.cjs --port 8765
```

The pinned official Actions workflow checks code, audits the tracked allowlist, copies only current `dist/` to `work/pages-site`, and deploys it. For another repository, select **Settings → Pages → GitHub Actions**. Runtime paths work below a repository subdirectory. Static hosting does not probe a local service-health endpoint.
